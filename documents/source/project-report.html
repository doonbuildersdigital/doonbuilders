07Security and release audit — step by step

1Code review

Pass
  • No dangerouslySetInnerHTML, innerHTML, eval, new Function or document.write anywhere in src/.
  • All 9 links that open in a new tab use rel="noopener noreferrer".
  • URL inputs are checked against allowlists: ?filter= and ?category= fall back to "all", and an unknown /projects/:slug shows the 404 page.
  • Browser storage holds only the theme choice (db-theme) and an intro-seen flag. No personal data is stored.
  • The contact form never claims to have sent a message unless the provider confirms it.

Minor notes: only the message field has a length limit (4,000 characters); the provider should limit the other fields. Sending is not idempotent, so if a request times out, a retry can send a duplicate enquiry.

2Dependency scan

Pass, with notes
  • npm audit --omit=dev: 0 vulnerabilities in libraries that ship to the browser.
  • npm audit (all): 7 vulnerabilities (5 high, 2 moderate), all inside Tailwind CSS 3.4.19's build-time chain: braces, micromatch, fast-glob, chokidar, postcss-nested, postcss-selector-parser. They are denial-of-service bugs that need malicious input files at build time. Visitors are not affected.
  • Patch updates available: vite 8.3.1 → 8.3.4, @vitejs/plugin-react 6.1.1 → 6.1.2, lucide-react 1.49 → 1.54, postcss 8.5.28 → 8.5.29.

Fix: run npm update now. Plan a migration to Tailwind CSS 4 (a breaking change) to clear the build-tool advisories. Do not run npm audit fix --force blindly, because it will break the styling.

3Secrets scan

Pass
  • Source, config, dist/ and doonbuilders-site.zip were searched for API keys, tokens, passwords, private keys and AWS / GitHub / Google / OpenAI key patterns. None found.
  • No .env file exists. .gitignore already excludes .env, .env.local and .env.*.local. .env.example holds only empty values.

Fix: add *.zip to .gitignore, so the 25 MB build zip is not committed by mistake.

4Authentication testing

Not applicable

The site has no login, user accounts, admin panel, sessions or cookies of its own, so there is nothing to test. If a CMS or admin area is added later, test this step again before launch.

5Authorization testing

Not applicable

There are no protected pages or private data. Everything in src/data/ and public/ ships to every visitor's browser, so treat all of it as public.

Review: the 2023 Dubai professional licence (licence no. 1174457) is published as full-page scans. The typed copy leaves out the owner's name, but the full-page scan may still show it in Arabic. The licence expired on 9 April 2024. Confirm that the owner agrees to publishing it.

6XSS / SQL injection testing

Pass
  • SQL injection: not possible. The site has no database and no server code.
  • XSS: React escapes everything it renders, and the code uses no raw-HTML functions. The SEO tags are set with setAttribute, which is safe. The JSON-LD schema is fixed text.
  • Values from the URL (filter, category, slug) only ever choose from fixed lists and are never printed back as HTML.
  • Link targets (phone, email, WhatsApp, socials, map) come from company.js, which only developers edit.

Keep in mind: when social or map links are added, use only https:// URLs.

7API testing

Partly tested
  • The only outgoing API call is the contact form (src/services/contactService.js).
  • Tested by reading the code: with no provider set, the form shows "Online enquiries are not connected yet" and gives the phone and email. A network or provider failure shows an error message with the phone number. The honeypot field silently drops bots.
  • The live request could not be tested, because no provider is configured.

Once a provider is set, test: a valid submission (does the email arrive?), an invalid key or endpoint (the error message should appear), offline mode, and a filled honeypot (nothing should be sent). Netlify Forms only works when the site is hosted on Netlify.

8Rate-limit testing

Action needed
  • The site has no server, so it cannot rate-limit anything itself. The form's only protections are a honeypot field and a disabled button while a message is sending.
  • A bot that skips the honeypot can flood the company inbox, and Web3Forms / FormSubmit free plans have monthly limits that spam can use up.

Fix before switching the form on: enable the provider's captcha and spam filter. Options: Web3Forms with hCaptcha, Netlify Forms with reCAPTCHA (Akismet filtering is on by default), or Cloudflare Turnstile with a custom endpoint. A custom API must enforce its own per-IP limit, for example 5 requests per 10 minutes.

9HTTPS / security-header check

Action needed
  • Live check (9 Oct 2026): https://doonbuilders.com failed the TLS handshake, so the domain has no working HTTPS. http://doonbuilders.com returned 404 Not Found from a "DPS/2.0.0" server. The website is not deployed on this domain yet.
  • Config check: netlify.toml and vercel.json set only Cache-Control. None of these headers is set: Content-Security-Policy, Strict-Transport-Security, X-Content-Type-Options, X-Frame-Options / frame-ancestors, Referrer-Policy, Permissions-Policy.

Fix: point the domain's DNS at Netlify or Vercel (both provide free automatic HTTPS) and add the headers shown in the appendix.

10Backup / restore test

Action needed
  • Restore test passed: only the source files were copied to an empty folder, then npm ci and npm run build were run. The build succeeded and produced identical file hashes, so the build is reproducible from source.
  • No backup exists: the git repository has 0 commits and no remote. Every file is untracked, so one disk failure or accidental delete would lose the whole project.
  • doonbuilders-site.zip holds only the built site (203 files), not the source code, so it is not a backup. Its paths use Windows \ separators, which can break when unzipped on Linux hosts.

Fix now: make the first commit and push it to a private GitHub repository. Keep a dated copy of public/images/archive/ and documents/ (the original scans) somewhere separate, such as Google Drive.

Appendix A — recommended security headers for netlify.toml

# Add below the existing [[headers]] blocks.
# The sha256 hash allows the inline theme script in index.html.
# If that script is edited, recompute the hash, or the theme will not load before first paint.
[[headers]]
  for = "/*"
  [headers.values]
    Strict-Transport-Security = "max-age=31536000; includeSubDomains"
    X-Content-Type-Options = "nosniff"
    X-Frame-Options = "DENY"
    Referrer-Policy = "strict-origin-when-cross-origin"
    Permissions-Policy = "camera=(), microphone=(), geolocation=(), payment=()"
    Content-Security-Policy = "default-src 'self'; script-src 'self' 'sha256-qWMmeLj9qnOJuXE87IHmK84/PcONhXQt+KDpeKgtj7k='; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com; img-src 'self' data:; media-src 'self'; connect-src 'self' https://api.web3forms.com https://formsubmit.co; frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'; upgrade-insecure-requests"

For Vercel, add the same six headers to vercel.json under "headers" with "source": "/(.*)". If a custom API endpoint is used, add its domain to connect-src. Load the site after deploying and check the browser console for CSP errors.
